# Milestone v0.3: Durability

**Status:** SHIPPED 2026-01-20
**Phases:** 17-22
**Total Plans:** 9

## Overview

Implement WAL, checkpointing, retry, and rate limiting for metrics — matching logs pipeline patterns exactly for production durability. This milestone establishes the durability infrastructure needed for reliable metrics ingestion.

## Phases

### Phase 17: Research Deep Dive

**Goal**: Understand ingest_v2 integration points, mrecordlog API, and chitchat position patterns
**Depends on**: v0.2 complete
**Research**: Complete (studied existing patterns in logs pipeline)
**Plans**: 1/1 complete

Plans:
- [x] 17-01: Metrics Durability Design Document (5 ADRs, integration specs, validated code patterns)

**Details:**
Created comprehensive design document synthesizing research findings into actionable specifications for Phases 18-22. Established 5 Architecture Decision Records:
- ADR-1: Separate metrics_wal_dir_path for WAL isolation
- ADR-2: Queue ID prefix metrics/ to prevent collision
- ADR-3: Reuse MRecord Doc/Commit without metrics-specific variants
- ADR-4: Per-shard positions identical to logs model
- ADR-5: Start with replication_factor=1 for v0.3

### Phase 18: Metrics WAL Integration

**Goal**: Integrate mrecordlog with MRecord format and per-shard queues
**Depends on**: Phase 17
**Plans**: 2/2 complete

Plans:
- [x] 18-01: MetricsWal struct with Arc<RwLock<MultiRecordLogAsync>>, queue CRUD, MRecord operations
- [x] 18-02: Queue ID formatting (ADR-2), capacity checking, force_delete, position range utilities

**Details:**
MetricsWal wraps MultiRecordLogAsync with thread-safe Arc<RwLock<>> access. Queue ID format: `metrics/{index_uid}/{source_id}/{shard_id}`. 9 unit tests for WAL operations.

### Phase 19: Checkpointing

**Goal**: Shard position tracking (replication, truncation, publish positions) with persistence to metastore
**Depends on**: Phase 18
**Plans**: 2/2 complete

Plans:
- [x] 19-01: MetricsShardPosition and MetricsIngesterState with two-phase locking
- [x] 19-02: WAL truncation logic with checkpoint delta integration

**Details:**
MetricsShardPosition tracks replication_position_inclusive and truncation_position_inclusive. MetricsIngesterState provides lock_fully() for atomic operations with correct lock order (WAL first, then inner state). Recovery-on-init infers positions from WAL queue_position_range.

### Phase 20: Cluster Gossip

**Goal**: Chitchat integration for cluster-wide position sharing via ShardPositionsService
**Depends on**: Phase 19
**Plans**: 1/1 complete

Plans:
- [x] 20-01: MetricsShardPositionsService actor for cluster-wide position gossip

**Details:**
MetricsShardPositionsService actor enables cluster-wide metrics shard position gossip via chitchat with separate `metrics.shard_positions:` prefix for isolation from logs.

### Phase 21: Retry & Error Handling

**Goal**: Exponential backoff with jitter, transient vs permanent error classification, recovery on startup
**Depends on**: Phase 20
**Plans**: 2/2 complete

Plans:
- [x] 21-01: MetricsIngestError enum with transient vs permanent error classification
- [x] 21-02: Recovery module with RecoveryStats and comprehensive tests

**Details:**
MetricsIngestError enum with 7 variants: 3 permanent (IndexNotFound, SourceNotFound, InvalidMetricsData), 4 transient (WalFull, IoError, MetastoreUnavailable, InternalError, Timeout). Recovery module with RecoveryStats tracking.

### Phase 22: Rate Limiting & Backpressure

**Goal**: Token bucket per shard (10MB burst, 5MB/s rate), memory capacity tracking, bounded channels
**Depends on**: Phase 21
**Plans**: 1/1 complete

Plans:
- [x] 22-01: MetricsShardRateLimiter with per-shard tracking, BackpressureError, check_can_append

**Details:**
MetricsShardRateLimiter with per-shard token bucket rate limiting using lazy initialization. BackpressureError distinguishes rate limit exceeded from capacity exceeded. check_can_append() combines WAL capacity and rate limit checks.

## Milestone Summary

**Key Decisions:**
- ADR-1: Separate metrics_wal_dir_path for WAL isolation
- ADR-2: Queue ID prefix metrics/ to prevent collision with logs
- ADR-3: Reuse MRecord Doc/Commit without metrics-specific variants
- ADR-4: Per-shard positions identical to logs model
- ADR-5: Start with replication_factor=1 for v0.3
- Two-phase locking order: WAL first, then inner state
- Error classification: permanent errors fail immediately, transient errors worth retrying
- Token bucket: 10MB burst, 5MB/s rate per shard

**Issues Resolved:**
- None - milestone executed cleanly

**Issues Deferred:**
- Rate limiter not wired into production ingestion pipeline (infrastructure ready, integration in future phase)
- Query integration with list_metrics_splits (v0.4)

**Technical Debt Incurred:**
- Compiler warnings for unused rate limiter types (will resolve when wired into production)
