# Milestone v0.7: Metrics Query

**Status:** ✅ SHIPPED 2026-01-25
**Phases:** 30
**Total Plans:** 4

## Overview

Wire DataFusion to read Parquet files from S3 via object_store, enabling queries against metrics data through a dedicated metrics query API endpoint. This milestone completed the query pipeline by bridging quickwit_storage to DataFusion's object_store abstraction.

## Phases

### Phase 30: DataFusion S3 Integration

**Goal**: Enable DataFusion to query Parquet files stored in S3/MinIO via object_store crate
**Depends on**: Phase 26 (Metrics Sequencer)
**Plans**: 4 plans

Plans:

- [x] 30-01: Object Store Bridge - StorageObjectStoreAdapter implementing object_store::ObjectStore
- [x] 30-02: DataFusion Integration - MetricsSessionContext::with_storage() and URI-based resolution
- [x] 30-03: Testing - S3-aware leaf search implementation and E2E tests
- [x] 30-04: Gap Closure - Fix RamStorage path handling and file size tracking

**Details:**

The phase implemented a storage bridge pattern where `StorageObjectStoreAdapter` wraps any `quickwit_storage::Storage` backend and exposes it via the `object_store::ObjectStore` trait that DataFusion requires.

Key components:
1. **StorageObjectStoreAdapter** (481 lines) - Read-only adapter implementing get, get_opts, get_range, get_ranges, head operations
2. **MetricsSessionContext::with_storage()** - Registers storage adapter with DataFusion RuntimeEnv
3. **MetricsTableProvider::with_storage_uri()** - Resolves S3 URLs and tracks file sizes from split metadata
4. **`/api/v1/{index}/metrics/query`** - New endpoint for SQL queries against metrics indexes

E2E test coverage validates:
- Basic SELECT queries via RamStorage
- Aggregation queries (SUM, AVG, MIN, MAX, COUNT)
- Multi-split queries across partitions

## Milestone Summary

**Decimal Phases:**

None - Phase 30 was the only phase in this milestone.

**Key Decisions:**

- Decision: Use object_store 0.12.4 (Rationale: Match DataFusion 51's transitive dependency)
- Decision: Read-only adapter for StorageObjectStoreAdapter (Rationale: DataFusion only needs read access)
- Decision: Dedicated /metrics/query endpoint instead of reusing /search (Rationale: Cleaner API separation)
- Decision: Search endpoint returns error for metrics indexes (Rationale: Force correct API usage)
- Decision: SQL interface for queries (Rationale: Full expressiveness vs limited JSON DSL)
- Decision: Track file sizes from split metadata (Rationale: DataFusion needs actual sizes for Parquet footer)

**Issues Resolved:**

- RamStorage path handling mismatch between upload and DataFusion lookup
- URI joining that incorrectly stripped all trailing slashes (ram:/// → ram:)
- File size handling (u64::MAX caused overflow, 0 caused "file too small" errors)

**Issues Deferred:**

- TEST-02: MinIO-specific integration tests (RamStorage validates same code path)
- Decimal128 Arrow type JSON serialization (shows type name; workaround: CAST to BIGINT)

**Technical Debt Incurred:**

- Decimal128 values not properly serialized in JSON response (low impact, workaround exists)
