# Milestone v0.2: Metadata

**Status:** SHIPPED 2026-01-18
**Phases:** 11-16
**Total Plans:** 9

## Overview

Optimize Parquet format, design metadata schema, and integrate with metastore for split staging and publishing. This milestone completes the metrics split lifecycle from ingest through publish, with efficient pruning via a two-tier strategy (Postgres + Parquet bloom filters).

**Depends on**: v0.1 complete

## Milestone Summary

**Key Decisions:**

- Two-tier pruning (Postgres + Parquet bloom): Postgres for 90%+ coarse filtering, bloom for fine-grained
- Cardinality threshold 1000: Tags <1000 values in Postgres, >=1000 use Parquet bloom filters
- Separate metrics_splits table: Independent schema evolution from log splits
- JSON array encoding for sqlx: Workaround for 2D array limitations, converted in SQL
- MetricsPublisher separate from Publisher: Metrics use different metastore API

**Issues Resolved:**

- Parquet RLE_DICTIONARY encoding API clarification (use dictionary_enabled instead)
- sqlx 2D array type limitations (JSON encoding workaround)
- Test schema mismatches for VARIANT type fields (VariantArrayBuilder helper)
- Test timing issues with async spawned tasks (permissive mocks)

**Issues Deferred:**

- Column order optimization (minimal benefit for columnar storage)
- MergePlanner integration for MetricsPublisher (not needed for initial integration)
- Sequencer integration for MetricsSplitsUpdateMailbox (simpler Publisher-only flow)

**Technical Debt Incurred:**

- Parquet upload in MetricsUploader is placeholder (empty files, needs output_dir from MetricsSplitBatch)
- Test helpers use permissive mocks due to async timing challenges
