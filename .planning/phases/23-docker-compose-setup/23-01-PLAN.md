<task type="auto">
  <name>Task 1: Add Minio service to Docker Compose</name>
  <files>docker-compose.yml, .minio/init-bucket.sh</files>
  <action>
Add Minio service to docker-compose.yml with `metrics-e2e` profile, following existing service patterns:

1. Add `minio` service:
   - Image: `minio/minio:RELEASE.2024-01-16T16-07-38Z` (stable release)
   - Profile: `metrics-e2e`
   - Ports: 9000 (API), 9001 (Console)
   - Environment: `MINIO_ROOT_USER=minioadmin`, `MINIO_ROOT_PASSWORD=minioadmin`
   - Command: `server /data --console-address ":9001"`
   - Volume: `minio_data:/data`
   - Healthcheck: `curl -f http://localhost:9000/minio/health/live`
   - Use `MAP_HOST_MINIO` env var pattern like other services

2. Add `minio-init` service:
   - Profile: `metrics-e2e`
   - Depends on: minio (service_healthy)
   - Image: `minio/mc` (Minio client)
   - Entrypoint: `/bin/sh -c`
   - Command: Run init script that creates `quickwit-metrics-test` bucket
   - Volume mount: `.minio:/etc/minio/init`

3. Add `minio_data` to volumes section

4. Create `.minio/init-bucket.sh` script:
   ```bash
   #!/bin/sh
   mc alias set minio http://minio:9000 minioadmin minioadmin
   mc mb --ignore-existing minio/quickwit-metrics-test
   mc anonymous set download minio/quickwit-metrics-test
   ```

Note: Postgres already exists with `postgres` profile. The `metrics-e2e` profile will be used to start both Minio and Postgres together in test commands.
  </action>
  <verify>
docker-compose --profile metrics-e2e config (validates YAML syntax)
docker-compose --profile metrics-e2e up -d minio postgres
curl -f http://localhost:9000/minio/health/live (returns 200)
  </verify>
  <done>Minio service added with metrics-e2e profile, init script creates test bucket automatically on startup</done>
</task>
