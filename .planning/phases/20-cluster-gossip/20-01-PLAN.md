Create MetricsShardPositionsService following the existing ShardPositionsService pattern exactly (quickwit-indexing/src/models/shard_positions.rs).

**Key elements:**

1. **Prefix constant:**
   ```rust
   const METRICS_SHARD_POSITIONS_PREFIX: &str = "metrics.shard_positions:";
   ```
   Use `metrics.shard_positions:` NOT `indexer.shard_positions:` to avoid collision with logs.

2. **LocalMetricsShardPositionsUpdate event:**
   - Define as `pub(crate) struct` with source_uid and shard_positions fields
   - Implement `Event` trait for EventBroker
   - Constructor `new(source_uid, shard_positions)`

3. **ClusterMetricsShardPositionsUpdate internal message:**
   - Private struct for chitchat callback → mailbox flow
   - Contains source_uid, shard_id, position

4. **MetricsShardPositionsService struct:**
   ```rust
   pub struct MetricsShardPositionsService {
       shard_positions_per_source: FnvHashMap<SourceUid, BTreeMap<ShardId, Position>>,
       cluster: Cluster,
       event_broker: EventBroker,
       cluster_listener_handle_opt: Option<ListenerHandle>,
   }
   ```

5. **parse_shard_positions_from_kv function:**
   - Parse key format: `{prefix}{index_uid}:{source_id}:{shard_id}`
   - Use rsplit_once(':') pattern from reference
   - Return ClusterMetricsShardPositionsUpdate

6. **push_position_update helper:**
   - Parse key/value, send to mailbox via try_send_message
   - Log error on parse failure or send failure

7. **Actor impl:**
   - `type ObservableState = ()`
   - `initialize()`: Subscribe to chitchat with prefix, replay existing state from all node_states

8. **spawn() class method:**
   - Create service, spawn actor, subscribe to LocalMetricsShardPositionsUpdate via event_broker

9. **Handler<ClusterMetricsShardPositionsUpdate>:**
   - Call apply_update, publish to event_broker if changed

10. **Handler<LocalMetricsShardPositionsUpdate>:**
    - Call apply_update
    - If changed: publish to chitchat AND event_broker

11. **Helper methods:**
    - `apply_update()`: Monotonic update (only keep max position per shard)
    - `publish_positions_into_chitchat()`: Format key, call set_self_key_value_delete_after_ttl
    - `publish_shard_updates_to_event_broker()`: Publish ShardPositionsUpdate event

**Dependencies to add to Cargo.toml:**
- quickwit-cluster (for Cluster, ListenerHandle)
- quickwit-actors (for Actor, Handler, etc.)
- fnv (for FnvHashMap)

**Module exports in mod.rs:**
- Add `pub mod shard_positions_service;`
- Re-export `LocalMetricsShardPositionsUpdate`, `MetricsShardPositionsService`

**Critical:** Mirror the reference implementation closely. The pattern is proven for logs; metrics should behave identically with different prefix.
