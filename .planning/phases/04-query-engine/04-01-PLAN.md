  <name>Task 2: Implement MetricsTableProvider for DataFusion integration</name>
  <files>quickwit/quickwit-metrics-engine/src/query/provider.rs</files>
  <action>
Create MetricsTableProvider implementing DataFusion's `TableProvider` trait:

1. Add async-trait dependency if not present (check workspace Cargo.toml first - DataFusion uses it)

2. `MetricsTableProvider` struct with:
   - `schema: SchemaRef` - Arrow schema from MetricsSchema
   - `parquet_files: Vec<PathBuf>` - Parquet file paths from split metadata
   - `base_path: PathBuf` - Base directory for resolving relative paths

3. Constructor:
   - `new(schema: MetricsSchema, splits: &[MetricsSplit], base_path: PathBuf) -> Self`
   - Collect all parquet_files from splits, join with base_path

4. Implement `TableProvider` trait (use `#[async_trait]`):
   - `fn as_any(&self) -> &dyn Any` - return self
   - `fn schema(&self) -> SchemaRef` - return schema clone
   - `fn table_type(&self) -> TableType` - return `TableType::Base`
   - `async fn scan(&self, state: &dyn Session, projection: Option<&Vec<usize>>, filters: &[Expr], limit: Option<usize>) -> Result<Arc<dyn ExecutionPlan>>`
     - Use `ParquetExec::builder()` to create execution plan from parquet files
     - Apply projection and filters if provided
     - Set target_partitions from state

The scan method should use DataFusion's `ParquetExec` (via `datafusion::datasource::physical_plan::parquet::ParquetExecBuilder`) to read the Parquet files. Use `ListingTableUrl::parse()` for file URLs.

Import pattern:
```rust
use datafusion::catalog::Session;
use datafusion::datasource::TableProvider;
use datafusion::logical_expr::{Expr, TableType};
use datafusion::physical_plan::ExecutionPlan;
use datafusion::datasource::listing::ListingTableUrl;
use datafusion::datasource::physical_plan::parquet::ParquetExecBuilder;
```
