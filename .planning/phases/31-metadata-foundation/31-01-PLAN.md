**column_type.rs** (~80 lines):
Port the Go `TypeIDFromPostFix` and `TypeID` enum. Key mappings:
- `__s` suffix -> TypeIDString = 14
- `__i` suffix -> TypeIDInt64 = 2
- `__nf` suffix -> TypeIDFloat64 = 10
- `__sk` suffix -> TypeIDSketch = 17

Create a `ColumnTypeId` enum with explicit discriminant values matching Go's iota:

```rust
#[repr(u64)]
pub enum ColumnTypeId {
    Int64 = 2,
    Float64 = 10,
    String = 14,
    Sketch = 17,
}
```

Implement `type_id_from_postfix(name: &str) -> Result<ColumnTypeId, SortSchemaError>` matching Go `TypeIDFromPostFix`.

Implement `type_id_from_string(s: &str) -> Result<ColumnTypeId, SortSchemaError>` matching Go `TypeIDFromString` (parses type name like "int64", "string", "float64").

**parser.rs** (~200 lines):
Direct port of Go `StringToSchema`. Follow the exact Go logic:
1. Split on `=` for optional name
2. Split on `/` for version suffix (require `/V#` with # >= 2 per strict V2-only decision)
3. Split on `|` for columns
4. For each column, handle `&` LSM cutoff marker (must not be first column, at most one marker)
5. Split column on `:` -- handle 1-part, 2-part, 3-part forms:
   - 1-part: `name` -> infer type from postfix, default direction (ascending for non-timestamp, descending for timestamp)
   - 2-part: `name:+/-` -> infer type from postfix, explicit direction
   - 3-part: `name:type:+/-` -> explicit type + verify matches postfix, explicit direction
6. Call validate_schema at end

**V2-only enforcement (per user-confirmed strict V2-only decision):** After parsing version, if `sort_version < 2` (i.e., INCORRECT_TRIM=0, TRIMMED_WITH_BUDGET=1, or no version), return `SortSchemaError::UnsupportedVersion`. Strings without `/V#` suffix default to version 0 and are rejected. /V1 strings are also rejected -- only /V2 and higher are accepted.

**display.rs** (~100 lines):
Port Go `SchemaToString` and `SchemaToStringShort`:
- `schema_to_string(schema: &SortSchema) -> String` -- full form with explicit types
- `schema_to_string_short(schema: &SortSchema) -> String` -- short form, omits type and default direction

**validation.rs** (~60 lines):
Port Go `ValidateSchema`. Key validations:
- Schema must have at least one column
- Column names must not be empty
- Column types must be valid
- Sort directions must not be Unknown
- `timestamp` column should be last and descending (warn but don't reject for flexibility)

**equivalence.rs** (~40 lines):
Port Go `EquivalentSchemas` and `EquivalentSchemasForCompaction`:
- `equivalent_schemas(a, b) -> bool`: Compare columns + LSM cutoff
- `equivalent_schemas_for_compaction(a, b) -> bool`: Compare columns only (ignore LSM cutoff)

**Error type:**
Create `SortSchemaError` enum in `mod.rs` with variants:
- `MalformedSchema(String)`
- `BadSortVersion(String)`
- `UnsupportedVersion { version: i32, minimum: i32 }`
- `MultipleCutoffMarkers`
- `CutoffOnFirstColumn`
- `EmptyColumnAfterCutoff`
- `CutoffInMiddleOfName(String)`
- `CutoffRequiresMultipleColumns`
- `InvalidColumnFormat(String)`
- `UnknownColumnType(String)`
- `TypeMismatch { column: String, from_suffix: String, explicit: String }`
- `UnknownSortDirection(String)`
- `ValidationError(String)`
Implement `Display` and `std::error::Error`.

**mod.rs** -- Public API re-exports:

- `parse_sort_schema("metric_name|timestamp/V2")` -> Ok (sort_version=2, meets V2 minimum)
