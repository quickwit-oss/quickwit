<task type="auto">
  <name>Task 1: Fix RamStorage path handling in MetricsTableProvider</name>
  <files>quickwit/quickwit-metrics-engine/src/query/provider.rs</files>
  <action>
The issue is in how `MetricsTableProvider::scan()` handles the "ram" scheme:

**Root cause analysis:**
1. `MetricsSessionContext::with_storage()` registers the adapter using `storage.uri()` which is "ram:///"
2. DataFusion uses this URL to lookup the registered object store
3. In `provider.rs::scan()`, for scheme "ram", it creates `ObjectStoreUrl::parse("ram://")` (missing trailing slash)
4. The path extraction in `extract_path_from_uri()` doesn't handle "ram" scheme at all - it falls through to the default case which returns the full URI

**Fix needed in provider.rs:**

1. Add "ram" case to `extract_path_from_uri()`:
```rust
"ram" => {
    // ram:///path/to/file.parquet -> path/to/file.parquet
    uri.strip_prefix("ram:///")
        .or_else(|| uri.strip_prefix("ram://"))
        .unwrap_or(uri)
        .to_string()
}
```

2. Fix the ObjectStoreUrl construction in `scan()` for "ram" scheme:
```rust
"ram" => ObjectStoreUrl::parse("ram:///")?,
```
This matches the URL registered by `with_storage()`.

3. Also handle the case where RamStorage files are stored with just paths (no ram: prefix in the stored path). The test uploads to path `{split_id}/{filename}` which gets the storage URI prepended to become `ram:///{split_id}/{filename}`. The path extraction needs to return just `{split_id}/{filename}`.

Confirm the fix matches storage.uri() output (ram:///) from context.rs line 101.

All tests pass.
