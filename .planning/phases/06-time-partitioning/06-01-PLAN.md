<objective>
Implement time-range partitioning for efficient metrics access patterns.

Purpose: Organize metrics splits into time-based partitions for fast query pruning. Metrics queries almost always filter by time range - partitioning enables O(log n) partition lookup instead of scanning all splits.

Output: TimePartition type, TimePartitionIndex for efficient lookups, partition-aware query pruning in SplitRegistry.
</objective>

Add TimePartitionIndex to partition.rs:

**TimePartitionIndex struct** with fields:
   - `granularity: PartitionGranularity`
   - `partitions: BTreeMap<u64, TimePartition>` - Key is bucket_start_secs for O(log n) range queries

Methods:
   - `new(granularity) -> Self` - Create empty index
   - `add_split(&mut self, split: MetricsSplit)` - Add split to appropriate partition (creates partition if needed)
   - `find_partitions(&self, range: &TimeRange) -> Vec<&TimePartition>` - Find partitions overlapping time range using BTreeMap range iteration
   - `all_partitions(&self) -> impl Iterator<Item = &TimePartition>` - Iterate all partitions
   - `partition_count(&self) -> usize` - Number of partitions
   - `total_splits(&self) -> usize` - Total splits across all partitions
   - `remove_before(&mut self, timestamp_secs: u64) -> Vec<TimePartition>` - Remove and return old partitions (for retention)

The BTreeMap enables efficient range queries:
```rust
// Find partitions overlapping [query_start, query_end)
// Start from first partition that could overlap (bucket_start <= query_end)
// Stop at first partition that can't overlap (bucket_end <= query_start)
```

<task type="auto">

  <action>
Enhance SplitRegistry to use TimePartitionIndex internally:

1. **Add fields** to SplitRegistry:
   - `partition_index: Option<TimePartitionIndex>` - Optional partitioned mode
   - Keep existing `splits: Vec<MetricsSplit>` for non-partitioned mode (backwards compatible)

2. **Add methods**:
   - `with_partitioning(granularity: PartitionGranularity) -> Self` - Create registry with partitioning enabled
   - `register(&mut self, split: MetricsSplit)` - Updated to route to partition_index if enabled
   - `prune_by_time_range(&self, range: &TimeRange) -> Vec<&MetricsSplit>` - Updated to use partition index if enabled:
     ```rust
     if let Some(index) = &self.partition_index {
         // Fast path: find relevant partitions first, then filter splits within
         index.find_partitions(range)
             .flat_map(|p| p.splits())
             .filter(|s| s.overlaps_time_range(range))
             .collect()
     } else {
         // Original path: scan all splits
         self.splits.iter().filter(...).collect()
     }
     ```
   - `partition_stats(&self) -> Option<PartitionStats>` - Return partition statistics if partitioning enabled

3. **PartitionStats struct**:
   - `granularity: PartitionGranularity`
   - `partition_count: usize`
   - `total_splits: usize`
   - `time_range: Option<TimeRange>` - Overall range covered

Tests: Compare pruning results between partitioned and non-partitioned modes, verify same results with better organization.
