<task type="auto">
  <name>Task 1: Enable bloom filters and RLE encoding on dictionary columns</name>
  <files>quickwit/quickwit-metrics-engine/src/storage/config.rs</files>
  <action>
Update `to_writer_properties()` to enable bloom filters and RLE encoding for dictionary-encoded columns:

**Part A - Enable RLE_DICTIONARY encoding:**

Since dictionary-encoded columns are sorted (metric_name, then tags), the dictionary indices will have long runs of the same value. RLE compresses these runs efficiently.

1. Enable RLE_DICTIONARY encoding for all dictionary-encoded string columns:
   - metric_name
   - tag_service
   - tag_env
   - tag_datacenter
   - tag_region
   - tag_host
   - service_name

2. Use `set_column_encoding(ColumnPath, Encoding::RLE_DICTIONARY)` for each column.

3. Import `parquet::basic::Encoding`.

**Part B - Enable bloom filters:**

1. Enable bloom filters on filtering columns (the ones used in WHERE clauses):
   - metric_name - always filtered in queries
   - tag_service
   - tag_env
   - tag_datacenter
   - tag_host
   - service_name

2. Use `set_column_bloom_filter_enabled(ColumnPath, true)` method.

3. Set bloom filter FPP (false positive probability) to 0.05 (5%) - good balance for metrics cardinality.

4. Set bloom filter NDV (number of distinct values) estimate to 10,000 for tag columns, 100,000 for metric_name (reasonable estimates for typical metrics workloads).

5. Do NOT enable bloom filters on timestamp_secs or value columns (range queries don't benefit from bloom filters).

Use parquet crate's WriterPropertiesBuilder methods:
- `.set_column_encoding(ColumnPath, Encoding::RLE_DICTIONARY)`
- `.set_column_bloom_filter_enabled(ColumnPath, true)`
- `.set_column_bloom_filter_fpp(ColumnPath, 0.05)`
- `.set_column_bloom_filter_ndv(ColumnPath, ndv)`

Import `parquet::file::properties::ColumnPath` and `parquet::basic::Encoding`.
